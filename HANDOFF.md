# HANDOFF — Firebreak

Operation Wolf-style gallery shooter by QuietByte. Godot 4.7.2 / GDScript. Version 0.3.7 =
stage 1 "River Village" only (12 stages planned), painted sprites with sticker outlines,
helicopter, 19 original weapons in a 3-slot loadout, cash economy + Store, grenades/launchers,
air strike (spares civilians), Rayan title screen, music/SFX/voice, optional global top 100.
Read `docs/DESIGN.md` first.

## Run
- Tests: `./tools/test.sh` (uses `godot` on PATH or `$GODOT`; on this PC `GODOT=~/.local/bin/godot`).
- Build: `GODOT=~/.local/bin/godot ./tools/build-linux.sh` → `build/linux/Firebreak.x86_64` and `build/Firebreak/`.
- Packages: `./packaging/build_linux.sh 0.3.7` → `dist/` (tar.gz, .deb; AppImage if appimagetool is present). `./tools/package-release.sh` exports and packs. `./tools/build-snap.sh` packs `firebreak-game` from the .deb (does not upload).
- Play: `./play.sh` (runs the exported build). Editor: `~/.local/bin/godot -e --path .`.

## Layout
- `scripts/stage_sim.gd` all game rules (no nodes; tests drive it directly).
- `scripts/stage_data.gd` JSON loading, validation, difficulty curve.
- `scripts/stage_view.gd` background, depth layers (far/mid/sky/near/pickups, each lit by
  `shaders/entity_light.gdshader`), effects, air-strike jets/bombs.
- `scripts/sprite_art.gd` draws the painted sprites (`assets/sprites/units|vehicles`), sized so
  each figure fills its hitbox. `scripts/sprite_meta.gd` is generated by `tools/art/sprite_meta.py`.
  `scripts/art.gd` now only draws the truck (no truck sprite yet).
- `scripts/title_screen.gd` + `shaders/logo_fill.gdshader` title art, embers, live logo.
- `scripts/weapons.gd` weapon data access (`data/weapons.json`), profile (user://profile.json:
  cash, owned, loadout, ammo, stages cleared), store rules (buy, equip, ammo, air strikes).
- `scripts/hud.gd` HUD + crosshair + weapon bar (`slot_rect/slot_at`, icons from
  `assets/ui/weapons/<id>.png`), cash panel and cash pop-ups. `scripts/main.gd` menus, input, audio cues, QA autopilot.
- `scripts/input_setup.gd` InputMap defaults + remaps (user://controls.cfg).
- `scripts/scores.gd` top ten (user://scores.json) + settings (user://settings.cfg, including the online opt-out).
- `scripts/online.gd` non-blocking POST of a qualifying campaign score to firebreak.quietbytehq.uk.
- `leaderboard/` Cloudflare Worker + D1 (see `leaderboard/deploy.sh`). Not part of the Godot export.
- `scripts/audio.gd` loads `assets/audio/<name>.ogg|wav|mp3` or `audio/` next to the executable;
  music intro->loop, named loops (rotor, heartbeat), rate-limited Rayan voice.
- `shaders/screen_fx.gdshader` vignette, hurt flash, blood-edge spatter, low-health pulse.
- Child villager art is deliberately NOT in the game (adults only); keep it that way.
- Frame cap: `Engine.max_fps = 60` (main.gd) + `application/run/max_fps=60`, vsync on.
- `data/campaign.json`, `data/stages/stage_01.json` stage definitions.
- `data/fp_weapons.json` first-person muzzle/rear points and `reload_poses` (0.3.4).
- `story/STORY.md` (opening briefing and travel map, 0.3.6) and `story/CATCHPHRASES.md`.
- `assets/logo/firebreak-512.png`, `firebreak-256.png` and `firebreak.svg`: the flaming-F app icon (also copied to `assets/ui/icon.png` for Godot).
- `packaging/build_linux.sh` and `packaging/firebreak.desktop`: Linux tar.gz, .deb and AppImage, following Nudge.
- `snap/snapcraft.yaml`: snap name `firebreak-game`, built from the .deb, `network` plug for the scoreboard. Version and the .deb filename must stay in sync with `project.godot`.
- `.github/workflows/ci.yml`: on a version tag, export Linux and Windows, package, attach a GitHub pre-release, build the snap and upload it to `edge`. Store credentials use the secret name `SNAPCRAFT_STORE_CREDENTIALS` (never commit the value).
- `_to_delete/` scratch and replaced files only. Safe for the owner to delete. Not exported or committed.

## Weapons, loadout, economy (0.3.0)
- `data/weapons.json` is the single source: per weapon category, price, mag, reserve
  (-1 = unlimited), max_reserve, issue_mags, drop_mags, ammo_price/ammo_pack, fire_rate,
  damage, spread, reload and sound/reload_sound/dry_sound; specials add kind, radius, blast_damage and
  flight; `economy` holds kill cash per kind (x band multiplier), gunner cash, civilian penalty
  and cash-drop values; `support` holds the Air Strike item. Names must stay original
  (`tests/test_weapon_data.gd` checks a banned real-name list).
- Slots: 0 pistol, 1 primary (SMG or rifle), 2 special. `StageSim.setup(..., profile)` copies
  the loadout and ammo in and tops each weapon up to issue ammo; `write_profile()` copies cash and
  ammo back. `main.gd` `_bank_stage()` banks once per stage (result, restart, quit) and saves
  unless in QA mode.
- Ammo drops refill the selected gun (the primary while the pistol or special is selected);
  grenade drops refill the special. Clicks on the weapon bar select a slot and never fire.
- Store: `main.gd` `show_store()` (tabs, list, detail with stat bars, Buy/Equip/Ammo, loadout
  strip). Reached from the title, the result screen and after saving a score.

## Adding a stage
Add `data/stages/stage_NN.json` (copy stage_01), set its background, scroll keyframes, band
zones (x ranges and ground y measured on the new panorama), waves and ambient spawners. Then
mark the stage `playable` in `data/campaign.json`. `StageData.validate()` and the
tests catch most data mistakes.

## QA capture (real rendering, exported build)
`build/Firebreak/Firebreak.x86_64 --resolution 1920x1080 -- --qa-run --qa-title --qa-pause-at=20 --qa-seconds=200 --qa-react=1.5 --qa-out=/abs/dir --qa-shots=30,60,100,140 --qa-tag=run`
Autopilot plays, saves PNGs and `<tag>-performance.json` (fps, frame times, GPU), then quits.
0.3.0 flags: `--qa-cash=N`, `--qa-loadout=id,id,..`, `--qa-slot-at=t1,t2,..` (cycles slots),
`--qa-store[=cat]` (walks the store tabs, buys sentinel_m4, captures `<tag>-N-cat-id.png`, quits).
QA runs never write the profile.
Extra 0.2.0 QA flags: `--qa-skip=T` (start at stage time T), `--qa-grenade-at=S`,
`--qa-airstrike-at=S`, `--qa-hurt-at=S` (applies a real 12-point hit for the hit-feedback capture).
The performance JSON has `raw_*` fields (wall-clock frame times, not Godot's smoothed delta)
and `vsync_note`. 0.2.0 laptop results: QA_REPORT.md; captures in `qa/laptop/v020/`.

## Enemy facing (0.2.1)
`StageSim.face_player()` turns riflemen, MG nests and paratroopers toward the player every frame
(dead zone 80 px at the centre). Front poses are painted turned to the viewer's left
(`SpriteArt.FRONT_NATIVE`), mirrored with `front_flip()`. `SpriteArt.muzzle_point()` gives the
barrel position for flashes, the warning ring and the start of the incoming round;
`enemy_fire` events carry `to` (screen point near the player) and `side` (-1..1) for the
round and the hit marker (`stage_view.gd` `_draw_incoming`). New poses: `tools/art/cut_front_v021.py`.

## Frame rate
60 fps cap (`application/run/max_fps` and `Engine.max_fps`). `main.gd` `_choose_vsync()` turns
vsync off when the refresh rate is not a whole multiple of 60 (e.g. 144 Hz), because vsync + a
60 cap paces frames 13.9/20.8 ms there; 60/120/240 Hz keep vsync. Revisit if tearing shows
on X11.

## Outlines and icons (0.3.0)
`tools/art/bake_outlines.py` (run with `HELI_SCALE=0.75`) bakes outlines into the unit and
vehicle PNGs and records pads in `assets/sprites/outline_v030.json`; `tools/art/sprite_meta.py`
then regenerates `scripts/sprite_meta.gd`. Re-bake from un-outlined masters only (they are in
`_to_delete/replaced_v030_art/`). Icons: `tools/art/cut_icons.py`, review sheet via
`tools/art/contact_sheet.py`. Run `godot --headless --import` after changing PNGs.

## First-person view and pause audio (0.3.1)
- `scripts/fp_view.gd` (node `main.fp`, CanvasLayer 1 under the screen effects; HUD is layer 2, so the
  weapon bar and reticle are always on top). Reads `sim.slot`/`sim.loadout`, `reload_timer`,
  `special_reload`; `main._on_sim_event` forwards every sim event to `fp.on_event`. "shot" = kick +
  flash + sparks; "grenade_throw" = kick (+ launch fire/smoke and back-blast for launchers), and from
  another slot the special is shown for 0.75 s; "airstrike" shows the radio hand for 1.5 s. Switch:
  lower 0.15 s, swap, raise 0.2 s. Reload dip. Frozen while paused. Arms turn 60% opaque when the
  reticle is over a solid part (64×64 alpha mask). Pictures: `assets/sprites/fp/`, points:
  `data/fp_weapons.json`; tools `tools/art/cut_fp.py`, `tools/art/fp_contact_sheet.py`.
- `scripts/audio.gd`: `pause_all()` / `resume_all()` / `clear_pause()`; `PAUSE_MUSIC = "music_pause"`;
  `ui_players` pool for `ui_*`/`store_*` sounds while paused. `main.pause_game` / `resume_game` call
  them; `start_stage` and `show_title` call `clear_pause`; `pending_sounds` wait while paused.
- QA flags: `--qa-fire-shots=t,...` forces one shot at each time at the nearest enemy away from
  villagers and captures `<tag>-fire-NNNs.png` on the next frame (flash and sparks visible);
  `--qa-no-fp` hides the view (for frame-rate A/B).
  0.3.4 flags: `--qa-reload-at=S` empties the mag and starts a reload; `--qa-aim-head` aims at the head zone of riflemen, paratroopers and MG gunners.
  0.3.5 flag: `--qa-fail-at=S` drops health to zero so the mission-failed screen can be captured.


## Campaign score and global top 100 (0.3.3)
- `Main.begin_run()` resets the campaign total; `bank_run_score()` adds the finished stage (clear or fail)
  once. START, “Play again” and the Store “Start mission” button begin a new run. “Restart stage” from
  pause keeps earlier stages in the total. `continue_run_to()` is ready for later stages.
- Clear bonus: `int(health)*20 + 10*int(round(seconds_left*2.5)) + int(round(accuracy*200))*10`.
- Qualifying scores (≥ 2,000) can be posted after name entry; Tab keeps the score on this computer only.
  The post never blocks the game. Send only name, score, mode `campaign`, version and last stage reached.
- Snap plug: `network`.
- Publish (owner): create `quietbytehq/firebreak`, `git push`, then `cd leaderboard && npx wrangler login && ./deploy.sh`.
  The admin URL is written to `~/.config/firebreak-scores-admin.txt` (not in the repo). Do not look up
  firebreak.quietbytehq.uk until after the first deploy.
- 19 suites, 1277 checks, 0 failures on the development copy and the laptop in 0.3.4 (0.3.3 was 1207).
  Local wrangler tests passed in 0.3.3. Live deploy and a post from the installed game to the live site
  still need the owner’s Cloudflare/GitHub steps.
